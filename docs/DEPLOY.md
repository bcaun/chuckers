# Развёртывание на своём VPS

Итоговая схема:

```
Telegram ──HTTPS──▶ Caddy :443 (сертификат Let's Encrypt) ──▶ Node.js 127.0.0.1:8080
                                                               ├─ мини-апп (статика)
                                                               ├─ API и WebSocket (игра с другом)
                                                               └─ бот: /start, платежи Stars
Данные: /var/lib/chuckers (база + аватары), бэкапы: /var/backups/chuckers
```

Всё работает в одном процессе Node.js, отдельная база данных не нужна.

---

## Что понадобится

| Что | Требования |
|---|---|
| VPS | Ubuntu 22.04/24.04 или Debian 12, 1 vCPU, 1 ГБ RAM, 10 ГБ диска — хватит на тысячи игроков |
| Домен | Любой: свой (`checkers.example.com`) или бесплатный поддомен (например, DuckDNS). Telegram открывает мини-аппы только по HTTPS с настоящим сертификатом |
| Бот | Токен от [@BotFather](https://t.me/BotFather) |
| Доступ | SSH под root или пользователем с `sudo` |

Подойдёт любой провайдер: Timeweb, Selectel, REG.RU, Aeza, Hetzner, DigitalOcean и т. п.

---

## Шаг 1. Создать бота

В [@BotFather](https://t.me/BotFather):

1. `/newbot` → имя (например, «Шашки») → username (например, `chuckers_game_bot`).
   Сохраните **токен** вида `123456789:AAH...`. Никому его не показывайте.
2. Мини-апп создадим на шаге 5, когда домен уже будет работать.

## Шаг 2. Направить домен на сервер

В панели регистратора домена создайте DNS-запись:

```
Тип: A    Имя: checkers    Значение: <IP вашего VPS>
```

Проверка (через 5–30 минут):

```bash
ping checkers.example.com     # должен отвечать IP вашего сервера
```

Если у сервера есть IPv6, можно добавить и запись `AAAA`. Если не уверены, что IPv6 работает, не добавляйте:
неверная запись `AAAA` мешает получить сертификат.

## Шаг 3. Установить одной командой

Подключитесь к серверу и выполните (подставьте свой домен, токен и short name):

```bash
ssh root@<IP сервера>

curl -fsSL https://raw.githubusercontent.com/bcaun/chuckers/main/deploy/install.sh -o install.sh
DOMAIN=checkers.example.com \
BOT_TOKEN=123456789:AAH-ваш-токен \
APP_SHORT_NAME=checkers \
bash install.sh
```

> Если репозиторий **приватный**, `curl` и `git clone` не сработают без доступа. Варианты:
> 1. Сделать репозиторий публичным: секретов в коде нет, токен хранится только на сервере.
> 2. Создать на GitHub токен с доступом только на чтение (Settings → Developer settings →
>    Fine-grained tokens → доступ к `chuckers`, Contents: Read). Затем скачать скрипт так:
>    `curl -fsSL -H "Authorization: token <TOKEN>" https://raw.githubusercontent.com/bcaun/chuckers/main/deploy/install.sh -o install.sh`
>    и добавить к команде установки `REPO=https://<TOKEN>@github.com/bcaun/chuckers.git`.

### Если на сервере уже есть nginx (другие сайты)
Скрипт сам это определит и подключит игру к существующему nginx: добавит отдельный сайт
`/etc/nginx/sites-available/chuckers` только для вашего домена и получит сертификат через certbot.
Другие сайты, брандмауэр (если он был выключен) и уже установленный Node.js 18+ он не трогает.
Можно указать почту для уведомлений Let's Encrypt: добавьте `EMAIL=you@mail.ru`.
Если порт 8080 уже занят другой программой, скрипт сам возьмёт первый свободный из 8080–8199 и напишет, какой. Можно задать порт явно: `PORT=8100`.

Что делает скрипт (его можно спокойно запускать повторно):

1. Ставит Node.js 22 (если подходящего ещё нет), git и Caddy, либо, если nginx уже стоит, certbot.
2. Создаёт системного пользователя `chuckers`, без права входа.
3. Клонирует код в `/opt/chuckers` и ставит зависимости.
4. Пишет настройки в `/etc/chuckers.env` (доступ только у root).
5. Регистрирует службу `chuckers` в systemd: автозапуск при загрузке и перезапуск при падении.
6. Настраивает HTTPS: Caddy или nginx с certbot. Сертификат Let's Encrypt продлевается автоматически.
7. Включает ночные бэкапы данных.
8. На чистом сервере включает брандмауэр (порты 22, 80, 443). На сервере с другими сайтами только добавляет 80 и 443, если брандмауэр уже был включён.

В конце скрипт выведет `Готово: https://checkers.example.com`.

## Шаг 4. Проверить

```bash
systemctl status chuckers                       # active (running)
journalctl -u chuckers -n 20                    # «Бот @… запущен»
curl -s https://checkers.example.com/api/config # {"botUsername":"…","payments":true,…}
```

Откройте `https://checkers.example.com` в обычном браузере. Должно появиться меню игры с надписью
«Нет связи с сервером» или ошибкой авторизации: вне Telegram вход не работает, и это нормально.

## Шаг 5. Подключить мини-апп в BotFather

1. `/newapp` → выберите своего бота → название, описание, картинка 640×360 (обложка) →
   GIF можно пропустить (`/empty`) → **URL:** `https://checkers.example.com` →
   **short name:** `checkers`. Он должен совпадать с `APP_SHORT_NAME` из шага 3.
2. Рекомендуется также: `/mybots` → ваш бот → **Bot Settings → Configure Mini App → Enable Mini App**
   с тем же URL. Тогда у бота появится кнопка «Открыть» в профиле, а приложение появится в поиске.
3. Платежи звёздами отдельно подключать **не нужно**: Telegram Stars работают у любого бота.

Проверка: откройте бота в Telegram и нажмите `/start`. Должно прийти сообщение с кнопкой «♟ Играть»,
а слева от поля ввода появится кнопка меню «Играть».

## Шаг 6. Проверить всё в Telegram

- [ ] Игра с ботом: доиграть партию, в профиле появилась запись.
- [ ] Игра с другом: отправить приглашение второму аккаунту, сыграть, сдаться, сыграть реванш.
- [ ] Покупка: купить, например, «Цвета шашек» за 100 ⭐ (понадобятся звёзды на аккаунте).
  Возврат тестовой покупки описан ниже.
- [ ] Загрузка фото на аватар.

## Обслуживание

### Обновление до новой версии
После того как в GitHub появились изменения:

```bash
bash /opt/chuckers/deploy/update.sh
```

Скрипт делает бэкап, забирает код, обновляет зависимости и перезапускает службу.
Идущие онлайн-партии при перезапуске обрываются, поэтому обновлять лучше, когда играет мало людей.

### Логи и управление

```bash
journalctl -u chuckers -f          # логи в реальном времени
systemctl restart chuckers         # перезапуск
systemctl stop chuckers            # остановка (база сохраняется на диск)
journalctl -u caddy -n 50          # проблемы с сертификатом/доменом
```

### Изменить настройки
```bash
nano /etc/chuckers.env
systemctl restart chuckers
```
Все параметры описаны в [`deploy/env.example`](../deploy/env.example).

### Бэкапы
- Каждую ночь в 04:15 данные (`/var/lib/chuckers`: база и аватары) архивируются в
  `/var/backups/chuckers/`, архивы старше 14 дней удаляются.
- Сделать бэкап вручную: `chuckers-backup`.
- Рекомендуется периодически скачивать архивы к себе:
  `scp root@<IP>:/var/backups/chuckers/*.tar.gz ./`
- Восстановление:
  ```bash
  systemctl stop chuckers
  tar -xzf /var/backups/chuckers/chuckers-ДАТА.tar.gz -C /var/lib/chuckers
  chown -R chuckers:chuckers /var/lib/chuckers
  systemctl start chuckers
  ```

### Переезд на другой сервер
1. На новом сервере выполните шаги 2–3 с тем же доменом.
2. Скопируйте свежий бэкап и восстановите его, как описано выше.
3. Переключите DNS на новый IP и выключите старый сервер. **Два сервера с одним токеном одновременно
   работать не могут**: бот получает обновления только в одном месте.

### Возврат звёзд
Если игрок просит вернуть деньги, найдите платёж в базе:
```bash
grep -o '"[^"]*":{"userId":"ID_ИГРОКА"[^}]*}' /var/lib/chuckers/db.json
```
Ключ записи — `telegram_payment_charge_id`. Вернуть звёзды:
```bash
source /etc/chuckers.env
curl -s "https://api.telegram.org/bot$BOT_TOKEN/refundStarPayment" \
  -d user_id=ID_ИГРОКА -d telegram_payment_charge_id=CHARGE_ID
```
Сама покупка при этом в игре не отзывается, её нужно снять вручную в `db.json`
(при остановленной службе).

## Если что-то не работает

| Симптом | Причина и решение |
|---|---|
| Скрипт: «Сервер не запустился» | `journalctl -u chuckers -n 50`. Чаще всего ошибка в `/etc/chuckers.env` |
| Сайт не открывается, ошибка сертификата | DNS ещё не обновился или указывает не туда (`ping домен`). Порты 80/443 закрыты у провайдера — проверьте его панель (внешний firewall). Смотрите `journalctl -u caddy -n 50` |
| В Telegram «Нет связи с сервером» | Сервер не запущен или URL в BotFather не совпадает с доменом |
| «Нет авторизации» внутри Telegram | Неверный `BOT_TOKEN`: мини-апп должен быть привязан к тому же боту, чей токен на сервере |
| Бот не отвечает на `/start` | В логе `getUpdates: Conflict` означает, что этот же бот запущен где-то ещё (другой сервер, ваш компьютер). Остановите лишний. Если у бота настроен webhook, удалите его: `curl https://api.telegram.org/bot<TOKEN>/deleteWebhook` |
| Приглашение открывает бота, но не игру | `APP_SHORT_NAME` не совпадает с short name из `/newapp` |
| Игра с другом зависает на «переподключаемся» | Между Caddy и сервером стоит другой прокси без поддержки WebSocket. С Caddy из скрипта всё работает |
| Не применилась покупка | В логе ошибки `refund failed` или `answerPreCheckoutQuery`. Пусть игрок напишет `/paysupport` |

## Безопасность

- Токен бота хранится только в `/etc/chuckers.env` с правами 600. В репозиторий его не добавляйте.
- Никогда не включайте `DEV=1` на боевом сервере: в этом режиме вход без Telegram и бесплатные покупки.
- Сервер слушает только `127.0.0.1`, а наружу всё отдаёт Caddy.
- Служба работает от отдельного пользователя без прав и может писать только в `/var/lib/chuckers`.
- Рекомендуется: вход по SSH-ключу вместо пароля и автоматические обновления безопасности
  (`apt install unattended-upgrades`).
